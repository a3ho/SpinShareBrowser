# 评论发布与删除

> 阶段 5/8 · 依赖 session-client · 优先级 P1

## Goal

原生界面发布/删除自己的评论：POST /song/{id} submitReview（浏览量+1 固有成本）、删评走专用路由，与既有评论读取面板整合，含已评状态切换。

## 背景与依据

- 评论读取（`GET /api/song/{id}/reviews`）已在产品中；写侧经会话表单（源码核实见 external/spinshare-api.md）。
- 发布 = `POST /song/{id}`（reviewRecommended/reviewComment，进门 views+1）；删除 = `/song/{songId}/review/{reviewId}/delete`（零浏览量）。
- 网站无评论编辑——"重评" = 删 + 发。

## Requirements

**做：**
- 现有评论面板加"写评论"入口：推荐开关 + 文本编辑器（字符限制对齐网站）。
- 发布：会话 POST；成功后局部插入自己的评论（不整页重拉）；views+1 成本为固有、不做 UI 噪音。
- 删除自己的评论：确认交互，专用路由。
- 已评状态：我评过的曲目显示徽标；重评引导为删+发。
- 我的评论列表：`GET /api/user/{id}/reviews` 公开读，按需 + LRU 节制（红线 3）。

**不做：**
- 他人评论的任何操作；评论编辑器富文本（对齐网站纯文本+推荐位）。

## 前端体验要求（所有者最高优先级）

- 编辑器与已评徽标交互稿先过所有者；发布中/失败/会话失效/字数超限全状态；锚定浮层或行内展开遵循既有浮层语言（不改变页面高度，红线 14）；中英同步；截图走查。

## Acceptance Criteria

- [ ] 发布/删除/已评切换契约测试全绿（fixture 基于模板镜像）。
- [ ] 局部插入不重拉测试；红线 3 节制自查。
- [ ] 隔离实例 E2E（所有者协助）+ 截图走查。
- [ ] spec 沉淀（frontend/reviews 扩展）。

## 风险与开放问题

- 新评论在列表中的插入位置与排序对齐（服务端按时间倒序，读取端行为为准）。
