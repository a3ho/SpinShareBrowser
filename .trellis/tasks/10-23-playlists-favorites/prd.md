# 歌单收藏：完整读写

> 阶段 3/8 · 依赖 session-client · 优先级 P0 · "收藏"需求的本体

## Goal

歌单完整读写：读公开 API、建（生成封面上传）、删、加歌（替换集+下标解析）、移除歌（零浏览量路由），含陈旧冲突检测。用户口径：**收藏 = Playlists**，数据在线上、随账号跨设备可见。

## 背景与依据

- 全部端点机制已源码核实，见 external/spinshare-api.md"网站表单通道"：
  - 创建 `POST /playlist/create`——**必须 multipart 上传封面 PNG，否则服务端静默 no-op**；CSRF 先取；新 id 从重定向取。
  - 删除 `GET /playlist/{id}/delete`——无 CSRF、一次即删（owner 校验）。
  - 加歌 `POST /song/{id}`——进门无条件 views+1（固有成本，所有者已接受）；**替换集语义**（先全移除再加回勾选）；**键为服务端数组下标而非歌单 id**，稳妥做法=解析渲染页 checkbox。
  - 移除歌 `GET /playlist/{id}/song/{songId}/delete`——**零浏览量**。
  - 读 `GET /api/user/{id}/playlists` / `GET /api/playlist/{id}`——公开无鉴权。
- **歌单无隐私字段，一律公开挂在用户主页**——UI 文案需让用户知情（"收藏夹是公开的"）。

## Requirements

**做：**
- **读 UI**：我的歌单列表（封面/标题/歌曲数）+ 歌单详情（曲目列表，与本地目录缓存交叉联动：已安装标记、缺曲跳转）。刷新走公开 API，按需 + LRU（红线 3）。
- **创建**：名称/描述对话框；客户端生成封面（预置占位艺术或首曲封面合成）；成功后读回校验（GET /api/playlist/{id}）。
- **删除**：原生确认对话框（不可逆操作，明确文案）；删除后列表即时一致。
- **加歌**：从曲目卡片/试听条入口"收藏到…"；执行 = 新鲜读自己的歌单 → 解析 /song/{id} 渲染页（取下标与勾选态）→ POST 完整成员关系 → 读回校验。已在歌单的显示勾选态、可反选（同一次 POST 完成）。
- **移除歌**：歌单详情内移除，走零浏览量专用路由。
- **陈旧冲突**：POST 前发现服务器状态与本地假设不一致（他端改动）→ 中止并重新拉取呈现，绝不盲目覆盖（替换集语义下陈旧写=复活已删成员）。
- 全部走会话客户端的串行节流队列；中英双语同步；失败保留最后确认状态（红线 13）。

**不做：**
- 歌单编辑（改名/描述/换封面 `POST /playlist/edit/{id}`）——本任务不做，留待有需求时（机制已核实可行）。
- 不做"同步安装"（阶段 4 的事）。
- 不做歌单封面自定义上传（只用生成的）。

## 前端体验要求（所有者最高优先级）

- design.md 交互稿先行："收藏到…"浮层与我的歌单面板必须交所有者选型后再实现。
- 全状态覆盖：加载 / 空歌单 / 错误 / 会话失效 / 陈旧冲突 / 未登录降级。
- 对齐既有设计语言（DESIGN.md）与锚定浮层/动效体系；图标控件带可访问名称（红线 12）；中英 i18n 同步（红线 16）。
- 隔离实例 + 截图视觉走查后才收尾。

## Acceptance Criteria

- [ ] fixture 契约测试：创建（含封面 multipart 与 CSRF）、删除、加歌（替换集 body 构造、下标解析）、移除、冲突中止路径全绿。
- [ ] 隔离实例 + 所有者账号 E2E：建→加两首→移除一首→删，网页端交叉验证结果一致。
- [ ] 浏览量核算：加歌操作每次恰好 +1，移除/建删为 0（E2E 时对照 song views 记录）。
- [ ] 交互稿经所有者过目；截图走查通过（前端质量门）。
- [ ] 未登录态 UI 优雅降级（隐藏写入口，读入口可保留公开歌单浏览）。
- [ ] spec 更新（frontend 层新增歌单 UI 规格；DESIGN.md 同步）。

## 风险与开放问题

- 封面生成的设计语言：占位艺术需符合项目审美（DESIGN.md 现有语系），design.md 出方案。
- 下标漂移：创建/删除歌单会使旧解析页下标失效——解析页缓存的有效期策略（每次写前重解析 vs 会话内短缓存）在实现时定，默认每次重解析（一次 GET 的 views 成本已含在加歌 +1 内——注意：**解析 GET 也 +1**，故加歌总成本为 GET+POST 共 +2，须在核算与文案中如实对待；若实测可仅 POST（凭公开 API 推导下标）则降为 +1，实现时验证）。

## 验证方式

本地全量单测 + fixture 契约测试 + 隔离实例 E2E（所有者协助段 checklist：操作序列 + 网页端对照 + views 核对）。
