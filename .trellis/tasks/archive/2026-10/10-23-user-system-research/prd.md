# PRD: Research SpinShare user-system integration feasibility

## Goal

回答：SpinShare Browser 能否（以及如何、以什么代价）接入 SpinShare 用户系统——登录会话、收藏（favorites）、发表评论/评分，以及"等"所隐含的其它账号功能（播放列表、关注等）。产出**证据支撑**的调研报告，不做任何产品代码改动。

## 研究问题

1. **鉴权机制**：SpinShare 网站与新客户端（client-next）如何登录？会话 Cookie / Bearer token / 第三方 OAuth？有无验证码或设备校验？
2. **端点清单**：登录/登出/当前用户/收藏列表/收藏增删/评论发表·修改·删除/评分/播放列表/关注——各自的方法、路径、参数、响应结构？官方是否公开文档或开源客户端可查证？
3. **CORS 与调用约束**：这些端点是否允许第三方源调用？CSRF 防护形态？从 WebView（127.0.0.1 页面）直接调用可行，还是必须经本地 Python 服务代理？
4. **架构适配**：凭证（Cookie/token）如何安全存储（状态目录、权限、退出、过期）？与本项目 CSP、本地 API 鉴权模型、错误翻译链如何融合？
5. **礼仪与红线**：登录态接口是否触发计数/通知？轮询收藏列表等读取是否需要节流？官方对第三方客户端的态度/条款？
6. **结论**：分级——哪些功能可"完美"接入、哪些有条件、哪些不可行/不建议，及理由。

## 方法与边界

- 证据来源：官方文档、官方开源代码（若有）、少量**无凭证**端点探测（只验证存在性/鉴权形态，不爆破、不灌请求、不带任何真实账号）。
- 不修改任何产品代码；不申请/使用真实账号；探测总量控制在个位数请求。
- 产出：`.trellis/tasks/10-23-user-system-research/research/report.md`（结论先行、证据引用、建议方案草图、风险清单）。
