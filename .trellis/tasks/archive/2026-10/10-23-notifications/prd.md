# 通知读取与清除

> 阶段 6/8 · 依赖 session-client · 优先级 P2

## Goal

通知读取与清除：会话页解析通知列表，/notification/clear/{id} 与 /notification/clearAll，仅用户打开时刷新（无后台轮询）。

## 背景与依据

- 通知**无 JSON 端点**（Connect 版需 ApiKey 已弃），网站侧靠登录页渲染的铃铛下拉；清除路由 `/notification/clear/{id}`、`/notification/clearAll` 已源码核实（无 CSRF、零浏览量）。
- 解析对象：会话态任意页的铃铛下拉 HTML（模板镜像 base/组件可构造 fixture）。

## Requirements

**做：**
- 顶栏铃铛入口（对齐网站心智、用本项目浮层语言）→ 打开面板时拉取并解析：类型/关联曲目/时间。
- 单条清除 + 全部清除（网站路由）。
- 未读角标：仅有活跃会话时显示；打开面板才刷新——**无后台轮询、无定时器**（红线）。
- 点击通知跳转对应曲目（本地目录内定位）。
- 清除后与列表读回一致性校验。

**不做：**
- 桌面系统级通知推送；轮询/长连接。

## 前端体验要求（所有者最高优先级）

- 铃铛与通知面板交互稿先过所有者；加载/空（"暂无通知"对齐网站空态文案心智）/解析失败/会话失效全状态；角标不闪烁不制造焦虑；中英同步；截图走查。

## Acceptance Criteria

- [ ] 解析/清除契约测试全绿（fixture 基于模板镜像）。
- [ ] 代码审查证明无任何定时/后台网络行为。
- [ ] 隔离实例 E2E（所有者协助）+ 截图走查。
- [ ] spec 沉淀。

## 风险与开放问题

- HTML 解析对改版敏感：解析器集中单模块 + 契约测试，改版影响面可控。
