# SpinShare 会话客户端模块

> 阶段 2/8 · 依赖 frontend-build-pipeline · 优先级 P0 · 全部用户功能的地基

## Goal

会话通道地基：内嵌登录窗建会话、DPAPI 加密 cookie 存储、CSRF/表单驱动器、写前新鲜读协议、串行节流写队列，薄切片端到端打通登录态。本任务只交付"登录/登出/连接状态"这一条薄切片，具体功能（歌单/评论/上传）在后续任务。

## 背景与依据

- 所有者已裁定走"本人网站会话 + 官方表单端点"通道，并当 Connect API 永不修复（红线 1 例外 + external/spinshare-api.md"网站表单通道"一节的全部源码核实事实）。
- 会话 cookie = 账号本体：本地加密存储、绝不入日志、随时可断开。
- 桌面壳当前只允许密钥 UI 地址导航（desktop-host spec），登录窗必须是独立的受控 WebView2 实例/窗口。

## Requirements

**做：**
- **登录窗**：独立窗口加载 spinsha.re 登录页，用户亲手登录（天然支持 2FA）；登录成功后经 CoreWebView2 CookieManager 提取会话 cookie，窗口关闭。绝不让用户把密码输进我们的 UI。
- **会话存储**：cookie jar 落状态目录，Windows DPAPI 加密（当前用户绑定），提供"断开"（清除）；任何日志/诊断输出不含 cookie 值。
- **表单驱动器**（核心）：GET 页面 → 解析（Symfony `form[_token]` CSRF、勾选框下标键）→ POST（urlencoded/multipart，UA 与登录窗一致）→ 跟随重定向 → 判定结果；响应变登录页 = 会话失效信号（返回结构化错误，UI 引导重登）。
- **写前新鲜读协议**：任何写操作前强制重读公开 API 获取当前状态（替换集语义的硬前提，见 spinshare-api spec）。
- **串行节流写队列**：所有写操作串行、请求间留间隔、失败退避不风暴；仅用户显式触发入队（红线）。
- **身份解析**：登录后解析自己的 userId（供公开 API 读自己的歌单/评论）。
- **本地 API**：`/v1/session/status|login|logout` 下发给前端；UI 薄切片 = 设置区登录按钮 + 已连接为 XX 的状态显示。
- **前端体验（所有者最高优先级）**：登录入口与状态 UI 的交互稿先过所有者再实现；会话失效提示、断开确认等全状态覆盖；中英同步。
- **测试**：基于 twig 模板构造的 HTML fixture 契约测试（CSRF 解析、下标键解析、重定向判定、会话失效判定）；DPAPI 加解密往返；队列串行化与间隔。纯本地，不碰真实站点。

**不做：**
- 任何具体写功能（歌单/评论/上传）——只把通道和队列建好。
- 不自动重登、不后台保活；会话失效只提示。

## Acceptance Criteria

- [ ] 隔离实例端到端：登录 → 状态显示已连接 → 断开 → 状态清除（此步需所有者提供账号协助验证）。
- [ ] cookie 存储文件为 DPAPI 密文；日志全量检索无 cookie 值。
- [ ] 契约测试覆盖：CSRF/下标解析、会话失效信号、串行队列顺序与间隔。
- [ ] 红线自查：无任何后台/定时网络行为；写队列仅 UI 触发入队。
- [ ] spec 新增 backend/session-client.md，沉淀通道契约。

## 风险与开放问题

- **我没有 spinsha.re 账号**：契约层全部用 fixture 本地验证；最终 E2E 需所有者协助（登录一次，或临时提供会话用于隔离实例调试，用完即断）。
- 登录窗的窗口形态（模态/非模态、品牌标识"由 spinsha.re 官方页面承载"的清晰呈现）在 design.md 定。
- spinsha.re 若有 remember-me cookie，是否一并保存以延长会话寿命——实现时探测决定。

## 验证方式

本地全量单测 + fixture 契约测试 + 隔离实例（用户协助段单列 checklist）。
