# 歌单同步安装

> 阶段 4/8 · 依赖 playlists-favorites · 优先级 P0 · 王牌差异化功能

## Goal

王牌功能：任意歌单一键同步安装到游戏目录，diff 只装缺、走既有事务管线、尊重冷却、可取消不强杀、只增不删。

## 背景与依据

- 线上歌单 × 本地事务化安装管线的交叉点——网站不装东西、官方客户端安装器弱且歌单写坏，这是本项目独有的能力。
- 红线 1：下载仅限用户显式点击、一次下载。本任务把"一次显式触发"定义为一次同步确认（确认后批量串行执行），此解释链记录于此，实现必须逐首串行 + 间隔。
- 红线 9：绝不强杀有活跃任务的进程；红线 2：冷却/退避/事务/恢复机制不可绕过。

## Requirements

**做：**
- 入口：我的歌单 / 他人公开歌单详情 → "同步到游戏"。
- **预览确认（灵魂交互）**：diff 歌单 vs 本地已装 → 展示将安装 N 首 / 已装跳过 M 首 / 不可用 K 首（下架 404、DLC 谱面标注），用户确认才执行。
- 执行：复用既有下载+安装两阶段事务管线，逐首串行 + 间隔；单首失败不中断整批，末尾汇总；可取消 = 停止后续任务、绝不强杀进行中的（红线 9）。
- 中断恢复：与既有崩溃恢复语义对齐（重开后状态一致）。
- 进度呈现：对齐安装器现有状态语言，后台队列 + 顶部状态，不阻塞用户其它操作。
- 大歌单（50+ 首）节流策略与诚实的预计时长。

**不做：**
- 自动/定时同步（仅显式发起）；反向卸载（绝不自动删游戏目录内容）；只装缺，无合并策略。

## 前端体验要求（所有者最高优先级）

- 预览确认与进度呈现的交互稿先过所有者再实现——这是本功能的门面。
- 全状态：diff 加载/无可安装/执行中/单首失败/取消/恢复/会话失效。
- 对齐安装器既有状态模型与设计语言；中英同步；截图走查。

## Acceptance Criteria

- [ ] diff / 串行 / 取消 / 恢复单测（本地 fixture，不碰真实站点）。
- [ ] 红线自查：不强杀、每首恰好一次下载、间隔存在、冷却语义明确（同步占冷却与否在 design.md 定并记录）。
- [ ] 隔离实例 E2E：小歌单端到端（所有者协助）。
- [ ] spec 沉淀（backend/install-pipeline 扩展 + frontend 状态呈现）。

## 风险与开放问题

- 超大歌单总时长与退避叠加；部分曲目 404 容错；与手动冷却的交互（倾向：同步占冷却）。
