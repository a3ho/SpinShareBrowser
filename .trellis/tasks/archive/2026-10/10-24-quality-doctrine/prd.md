# 高维质量原则与自我审查体系

## Goal
8 个新缺陷的根因分析、更高维度原则提炼、自我批判/审查/测试流程设计。**本轮只分析设计，不写功能代码。**

---

## 一、8 个缺陷的根因分析

### 1. 登录窗口不在用户默认浏览器打开 & 登录后返回太慢
**表象**: pywebview 内嵌窗口不如系统浏览器好用，登录成功后检测延迟。
**根因**: 我把"独立 WebView2 窗口"等同于"打开系统浏览器"。WebView2 窗口不抢焦点、不显示在任务栏、用户可能找不到它。检测成功依赖轮询（2s 间隔），登录后实际延迟 2-4 秒。
**违反的原则**: 「用户路径不可被打断」——登录是用户已有心智模型的操作（打开浏览器→登录→返回），我用自定义窗口打破了它。

### 2. 最大化窗口时播放器区域全不可点击
**表象**: 最大化=所有播放器按钮变成拖动区；还原后=播放器可点但拖动失效。
**根因**: `publishWindowRegions` 的 `excluded` 矩形计算或传输在 maximized 状态下失效。可能原因：(a) `--top` CSS 变量在最大化时被重置导致 headerHeight=0，整个顶栏被排除；(b) `SetWindowRgn` 在 maximized 时坐标系不一致；(c) `scheduleWindowRegions` 在最大化后没有触发（ResizeObserver 可能不 fire）。还原后"无法拖动"说明还原时 regions 也没有正确更新——排除矩形覆盖了整个标题栏。
**违反的原则**: 「状态矩阵全覆盖」——窗口有 normal/maximized/minimized/DPI 四种状态，我只在 normal 下测试过。

### 3. 设置里谱面自动更新的文案和交互
**表象**: 名称不精确（应为"谱面自动更新"）、描述应放 tooltip 而非 label。
**根因**: 我把功能描述直接放在 label 里，没有遵循项目已有的"标题 + 小问号 tooltip"模式（"关闭窗口时"旁边就有小问号）。
**违反的原则**: 「信息层级三分离」——标题、简述、详细说明各有归属位置。

### 4. 谱面自动更新开关无法操作
**表象**: 点击无反应，无法关闭。
**根因**: label click handler 和 checkbox change handler **双重触发**——label click → checkbox.checked 切换 → change event → setAutoUpdate()，同时 label click handler 也直接调 setAutoUpdate()。两次调用竞争，autoUpdateBusy 互斥导致行为不可预测。更深层：我加了显式 JS click handler 是因为 CSS 隐藏的 checkbox 可能收不到原生 label 转发——但真正的问题是 `position: absolute` + `opacity: 0`` 的隐藏方式在 WebView2 中可能完全移除了 input 的可点击性。
**违反的原则**: 「单一触发路径」和「标准组件优先」——应该用项目已有的 `.form-switch` 或类似成熟模式。

### 5. 0 评论谱面评论按钮没反应
**表象**: 点击评论按钮，抽屉不打开。
**根因**: 我改了 `reviewsOpen` 和 click handler 的入口条件，但**没有追踪完整链路**到出口。0 评论时 `loadInlineReviews` 的行为：`readReviews` 返回空列表 → `renderAllReviews` 可能因为空列表直接 return false → `cell.target.hidden` 永远不被设为 false → 用户看不到抽屉。链路中的 `syncReviewVisibility` 需要知道抽屉应该打开，但它依赖 `reviewsOpen(cell)`，而 `reviewsOpen` 虽然不检查 count 了，但 `renderAllReviews` 内部还有其他检查（比如 `result.total > 0`）。
**违反的原则**: 「全链路走查」——我只改了入口，没有追踪到最终 DOM 状态。

### 6. 账户菜单浮窗位置错误
**表象**: 点击头像后浮窗出现在错误位置（见截图红框）。
**根因**: `positionAccountMenu` 在 `showPopover()` 后执行，但 popover 首次显示时 `offsetWidth/offsetHeight` 可能为 0（还没有 layout）。定位基于错误的尺寸，导致浮窗出现在 (0,0) 或错误偏移处。另外 rAF 循环可能在首次定位前就启动了，用 0 尺寸计算了位置。
**违反的原则**: 「浮层定位必须在显示后测量」——需要强制 reflow。

### 7. 歌单应该登录后立即预加载
**表象**: 点击收藏要等首次网络请求完成。
**根因**: "即时打开（缓存先行）"的前提是缓存有数据，但歌单只在用户**第一次点收藏**时才开始 fetch。登录成功 → 数据可用之间有一个空白窗口。
**违反的原则**: 「预测性数据加载」——登录成功后用户的下一步操作是确定的（看歌单/发评论），应立即预加载。

### 8. 展开所有评论时排版丑
**表象**: 评论区的用户名、时间、内容挤在一起，没有视觉分隔（见截图红框标注的三个评论）。
**根因**: "展开所有评论"（pinned 模式）下的评论渲染可能缺少 inline 模式的分隔样式。在 pinned 模式下，`cell.target.classList.add('is-pinned')` 可能改变了布局（比如移除了卡片边界、改变了背景），导致评论条目之间的视觉分离丢失。我没有在"展开所有"模式下做截图走查。
**违反的原则**: 「全模式视觉走查」——每个功能有多种展开模式，我只验证了默认模式。

## 二、更高维度原则（P1–P8）

### P1: 用户路径不可被打断
用户已有的操作心智模型不可被自定义实现替代，除非替代方案严格更优。登录→系统浏览器；按钮→即时反馈。

### P2: 状态矩阵全覆盖
窗口（normal/maximized/minimized/DPI）× 功能（每个交互控件）= 测试矩阵。状态变更后全部控件重新走查。

### P3: 信息层级三分离
标题（≤4字）+ 描述（一句话在控件旁）+ 详细说明（小问号 tooltip）。

### P4: 单一触发路径 + 标准组件优先
一个交互 → 一个事件 → 一个状态变更。禁止双入口。开关用标准 HTML 结构，不自定义 hack。

### P5: 全链路走查
修改任何交互行为时，从用户点击到最终视觉反馈画完整链路：click → handler → state → DOM → CSS。每一环确认。

### P6: 预测性数据加载
里程碑事件（登录、页面就绪）后，预测下一步操作并预加载数据。用户永远不等待首次加载。

### P7: 全模式视觉走查
每个功能在所有展开/折叠/全局/单卡模式下截图走查。

### P8: 浮层定位在显示后测量
popover 先 show → 强制 reflow（`void el.offsetWidth`）→ 再定位。所有 popover 共用一套定位引擎。

## 三、自我批判

### 我为什么反复犯同类错误

1. **E2E 验证不够深**: 验证了"代码执行了"但没验证"用户看到了什么"。开关 checked 属性变了 ≠ 用户能点击它；disabled=false ≠ 点击后抽屉打开。修复验证停留在 DOM 属性层面，没有到**视觉呈现**层面。

2. **测试全绿当作完成**: 测试只覆盖我想到的场景。用户在最大化、系统浏览器、连续操作等真实场景中的体验，不在我的测试内。

3. **修改碎片化**: 改了 click handler 但没追踪 renderAllReviews → target.hidden 这条完整链。每次修复只看直接相关的代码。

4. **浮层定位没有系统方案**: 每个浮层手写一个 position 函数，每次都有不同的 bug。应该有统一的浮层引擎。

5. **交付前没有全模式走查**: "展开所有评论"模式从未截图走查过。

### 我应该做什么

1. **每次修复必须以截图收尾**: 不只检查 DOM，要截图看用户实际看到什么。
2. **修改前画链路图**: 从点击到视觉反馈，每一环标注"改了吗？"
3. **建立统一浮层引擎**: 所有 popover 共用一套定位/跟随/守卫，不重复手写。
4. **发布前状态矩阵检查**: normal + maximized 两种窗口状态下走查全部控件。
