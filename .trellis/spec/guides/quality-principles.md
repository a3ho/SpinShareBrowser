# 质量原则与自我审查体系（永久 spec）

> 本文件从 2026-10-24 的 8 个缺陷根因分析中提炼，是所有后续开发的强制性质量标准。

## P1: 用户路径不可被打断
已有操作心智模型不可被自定义实现替代，除非严格更优。登录→系统浏览器；按钮→即时反馈。**任何交互在 100ms 内必须有可感知的反馈。**

## P2: 状态矩阵全覆盖
窗口状态（normal / maximized / minimized / DPI-changed）× 全部交互控件 = 测试矩阵。任何状态变更后**必须**对全部控件重新走查。发布门禁：normal + maximized 两种状态全控件截图走查。

## P3: 信息层级三分离
- **标题**: ≤4 字短名词（"谱面自动更新"）
- **描述**: 一句话放在控件旁（可选）
- **详细说明**: 小问号 tooltip，完整表述行为和边界

## P4: 单一触发路径 + 标准组件优先
一个交互 → 一个事件 → 一个状态变更。禁止双入口（如 label click + checkbox change）。开关用标准 `<label><input></label>` 结构。不造轮子。

## P5: 全链路走查
修改任何交互行为前，从用户点击画到最终视觉反馈的完整链路：
`click → event handler → state change → DOM update → CSS rendering`
**每一环标注"这环改了吗？这环的行为是否正确？"** 不改完整链路不交付。

## P6: 预测性数据加载
里程碑事件（登录成功、页面就绪）发生时，预测用户下一步操作并立即预加载所需数据。用户永远不应该"等待首次加载"。

## P7: 全模式视觉走查
每个功能在所有展开/折叠/全局/单卡模式下都要**截图**走查。"展开所有评论"和"单卡展开"是不同视觉状态，分别验证。

## P8: 浮层定位在显示后测量
popover 先 `showPopover()` → 强制 reflow（`void el.offsetWidth`）→ 再定位。所有 popover/浮窗共用一套定位引擎（锚定 + 视口守卫 + rAF 跟随 + 生长动效），不每个手写。

## 自我批判记录（2026-10-24）

1. E2E 验证停留在 DOM 属性层（checked/disabled），未到视觉呈现层（用户能否点击、能否看到抽屉打开）
2. 测试全绿当作完成，但测试只覆盖我想到的场景
3. 修改碎片化——只改入口，不追踪到出口
4. 浮层定位每个手写，没有系统方案
5. 交付前没有全模式截图走查

## 自我审查流程（每次修复必须执行）

1. **修改前**: 画全链路图（P5），标注每一环
2. **修改后**: 从用户视角截图验证（不只 DOM）
3. **全模式**: 该功能的所有模式/状态截图走查（P7）
4. **状态矩阵**: 如果涉及窗口/布局，normal + maximized 两种状态走查（P2）
5. **测试更新**: 测试反映新行为，不是放松断言绕过问题
